# Phase 4 — Prototype

**Goal:** Plan and describe a realistic façade — not a real product. Build only what customers will see and interact with during the test.

The philosophy: **fake it till you make it.** The prototype only needs to be convincing enough for a 1-hour interview.

---

## Exercise 1: Choose the Prototype Medium

Based on the storyboard, help the user decide the best format:

| Type | Use when... | Tools |
|---|---|---|
| App / UI screens | Testing a digital product flow | Figma, Keynote, screenshots |
| Landing page | Testing messaging and value prop | Simple HTML, Webflow, Carrd |
| Document / deck | Testing a pitch, onboarding, or report | Google Slides, Notion |
| Physical / service | Testing a real-world interaction | Paper, props, role-play script |
| Wizard of Oz | Testing an automated system manually | Live chat, human-in-the-loop |

Ask the user: *"What's the minimum surface area needed for a customer to have the key experience from your storyboard?"*

---

## Exercise 2: Assign Roles

Divide the prototype work into roles. Claude can advise on each; the user assigns ownership (even if they're doing it all solo):

- **Makers** — Build the core screens or content (follows the storyboard frame by frame)
- **Stitcher** — Ensures the prototype flows consistently end to end; catches gaps between frames
- **Writer** — Writes all real copy — headlines, CTAs, labels, error messages. No placeholder text.
- **Asset Collector** — Gathers images, icons, data, or any supporting content needed
- **Interviewer** — Prepares the Phase 5 interview script (can start now)

Ask the user: *"Which of these roles feel most challenging or time-consuming for you? That's where to focus first."*

---

## Exercise 3: Content Outline

Walk through the storyboard frame by frame and define what needs to be built for each:

For each frame, capture:
- **What the customer sees** — screen, document, or environment
- **Real copy needed** — headlines, labels, body text
- **Assets needed** — images, icons, data
- **Interactions** — what can the customer click, read, or do?

Flag any frames that require decisions before building (e.g., unclear UI flow, missing data).

---

## Exercise 4: Trial Run Plan

Before Phase 5, the prototype needs a dry run. Help the user plan it:

1. **Who plays the interviewer?** (Usually the user — Claude can help prep the script)
2. **Walkthrough check:** Can a stranger navigate the prototype without explanation?
3. **Timing:** Does the prototype fit within a 30–45 minute interview window?
4. **Failure modes:** What breaks most easily? What's the fallback?

---

## Phase 4 Artifacts

Summarize and confirm with the user before proceeding:

1. **Prototype medium** — chosen format and tools
2. **Role assignments** — who owns what
3. **Content outline** — frame-by-frame build list with copy and assets
4. **Trial run plan** — logistics and known risks
5. **Interview script draft** — opening, context questions, prototype walkthrough cues (see @templates.md)
